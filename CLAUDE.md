# binding-bench — working in this repo

A benchmark of whether a language model keeps track of who holds what, who *I* and *you* refer to, and whether it
learns a new rule from the examples in its prompt. `README.md` is the overview; `CONTRIBUTING.md` holds the gates.
Machine- or team-specific guidance, if any, lives in `CLAUDE.local.md` (git ignores it).

## What the benchmark is
- **Binding:** whether a model keeps track of who holds what (static lookup, update, set binding) and who *I* / *you*
  refer to (deixis, the stage gauges). **Fluid ICL:** learning a new rule from the prompt's examples (fluid F1–F4),
  against **crystallized** recall in the same few-shot frame (C0). **Riders:** entity-state tracking (boxes × ops) in
  four registers (code / narrative / screenplay / chat); `riders.lite` is the small in-loop slice.
- **Scoring:** closed-set log-prob of each candidate answer's first token; an exact tie between candidates splits the
  credit. Every battery is a frozen, sha256-pinned prompt file (pins in `src/binding_bench/binding/batteries.py`); a
  run refuses a file whose bytes or rendered prompts differ from the pin.
- **Registry** (`src/binding_bench/registry.py`): one row per eval: construct, batteries, recipe, clean readings,
  floor, flags (model-relative: reading, finding, panel, test), audit status.

## The laws
- **`fair` 4-shot is the few-shot reading; 0-shot is the floor.** `fair` = 4 exemplars balanced on every cell
  component. Cell-matched 3-shot teaches the answer's role (flip test).
- **An eval changes only on validity grounds** (rendering invariance, off-construct-lever insensitivity, item
  shortcuts), never because a score is low. A re-rendering must reduce spread, not raise the score.
- **Pre-register every test** (PREREG before any row is scored); amend openly in a dated ADDENDUM below, never above.
- **Verdicts are model-relative.** A flag names its panel; an eval-level verdict needs the flag on ≥3 models (panel:
  kotodama-tsumugi, Qwen3-1.7B, Pythia-1.4B, SmolLM2-1.7B, OLMo-2-1B, Qwen2.5-7B, Llama-3.1-8B, OLMo-2-7B).
- **The construct-separation claim is withdrawn** (replication failed). Each eval stays its own bar until a construct
  grouping is earned.
- **A new battery version is a new name plus a new pin**, beside the old one. Never re-pin in place.
- Before calling a pin lost, look for its recipe in the tests (bp-v3.2 was seed 2031, regenerated byte-exact).

## Code style
- One table per fact; never restate a pin, recipe or construct as a literal elsewhere.
- Comments state what is true now: no dates, no edit narration, no bare TODO. Referents only to things in this repo
  or public URLs.
- Push only when the gates in `CONTRIBUTING.md` pass, as checked by the commands themselves. A scorer change ships
  with a test or a parity check.
- Strong typing (dataclasses / pydantic), real error handling, refusals over silent fallbacks.
- Public prose (README, docs) is third person, timeless and scoped.
